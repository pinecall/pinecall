# What the console reads beside the agent's endpoints

The console is one client of the gateway; every screen is an endpoint of [gateway-api.md](gateway-api.md)
or of the pages beside it. This page is the endpoints that exist for a screen and no worker:

| endpoint | scope | what |
|---|---|---|
| `GET /v1/usage?after=&limit=` | `usage` | (`limit` 1 to 500, the default; outside it `422` with the field named) the org's metered rows after the cursor, `{rows, totals, next}`; one row per `call.summary`, `call.score` and `evals.spent` folded, the cursor the store's position so a billing consumer resumes losslessly |
| `GET /v1/insights?day=&days=&agent=` | `calls` | whole UTC days of the key's environment and scope: the window of `days` (1, 7 or 30; 1 by default) ending on `day` (today by default), and with `agent` that agent's calls alone. `{day, days, timezone, conversations: {now, before}, resolved_rate, median_e2e_s, spend_usd, channels: {phone, web, whatsapp}, judged, passed, escalated, mean_length_s, endings: [{reason, count}], series: [{day, phone, web, whatsapp, spend_usd, judged, passed}], sessions_total, live, agents: [{slug, calls, score, spend: {llm_usd, stt_usd, tts_usd, phone_usd, platform_usd, minutes, per_minute_usd}}], stages: [{stage, vendor, model, turns, median_s, p95_s, confidence}], budget: {limit_usd, spent_usd_month}}`. `before` is the calls of the window of the same length right before; `judged` the calls a judge settled and `passed` those no judge broke; `escalated` the calls a person took part in; `mean_length_s` over the calls that ended; `endings` how they ended, the most first; `series` one row per day of the window, a day with no call included. Any other `days` is a 400. The budget is the org's across both environments, and a call's cost counts in the month (UTC) its summary was written, the month of the window's last day; `stages` is each stage of the window's turns by the vendor and model its report names (see `docs/wire/metrics.md`, "Per day"); an agent's `spend` is what its calls of the window cost by stage, off their summaries' rows (the platform's own compute rows under `platform_usd`), and per minute of the calls that ended: what to optimise first |
| `GET /v1/insights/series?day=&days=&agent=` | `calls` | the window of `GET /v1/insights` (the same query) day by day, what the Observability screen draws. `{day, days, agent, timezone, series: [{day, calls, finished, escalated, spend_usd, mean_length_s, e2e_median_s, e2e_p95_s, endings: [{reason, count}], stages: [{stage, turns, median_s, p95_s}], judges: [{name, held, judged}], tools_ran, tools_failed}], vendors: [{stage, vendor, model, turns, median_s, p95_s}]}`: one row per UTC day of the window, a day with no call included; `stages` are each day's stage with every vendor and model added; `vendors` are the whole window's stages by vendor and model (`vendor` is empty and `model` null when a turn's report named none), read off the stage histograms the seal counted (`docs/wire/metrics.md`, "Per day") |
| `GET /v1/insights/tools?day=&days=&agent=` | `calls` | every tool the window's calls ran, the same query. `{day, days, agent, tools: [{name, ran, failed, median_s, last_error: {call, at, text} \| null}]}`: `ran` counts every result of the tool and `failed` those that carried an error; `median_s` is read off the tool's seconds, which a gateway timeout has none of; `last_error` is the newest failure of the window (`at` in unix seconds, `text` the tool's error). The most failed first, then the most run, then by name. Counted when each call was sealed, so a call still going is not in it; erasing a call takes its `last_error` away and keeps the counts |
| `GET /v1/insights/slow?day=&days=&agent=&limit=` | `calls` | the slowest turns of the window's calls, the same query and `limit` (1 to 50; 10 by default). `{day, days, agent, turns: [{call, agent, seq, name, at, e2e_s, hears_s, thinks_s, tools_s, speaks_s}]}`, the slowest `e2e_s` first: `seq` is the agent turn's entry, `at` its time in unix seconds, `name` the caller's name when the line carried one, `hears_s` the transcription delay of the caller's turn right before, `thinks_s` the model's first token, `tools_s` the seconds of the tools asked in that turn's speech, `speaks_s` the voice's first byte; each is null when the turn did not report it. Each call keeps its three slowest turns when it is sealed; erasing the call erases them |
| `GET /v1/insights/drift?agent=&before=&after=` | `calls` | what moved for one agent of the key's environment and scope between two sides, each a day (`2026-09-29`) or a version of its settings (`v3`); by default today against the day before, in UTC, and a side that is a version needs the other named. The answer is `{agent, world, before, after, judges, stages, versions}`: each side as asked with the versions its calls ran (`{day, version, versions}`); each judge with `{held, judged, pass_rate}` on each side, `moved` (the pass rate after minus before) and `criteria_changed` (the question it asked is not the same text on both sides, so the move may be the judge's, not the agent's); each stage by vendor and model with `{turns, median_s, p95_s, confidence}` on each side and `median_moved_s`, `p95_moved_s`; the most moved first. `versions` is every version either side ran or that was set between the first day's start and the last day's end, each `{version, holder, author, note, set_at, ran_before, ran_after}`: what changed and who changed it. Read from what each call's seal counted (`docs/wire/metrics.md`, "Per day"), so a call still going is not in it |
| `GET /v1/limits` | any key | each quota of the key's environment as `{limit, used}` (`minutes`, `messages`, `llm_tokens`, `concurrent_calls`, `agents`, `seats`, `numbers`, `evals`, `simulations`, `memory_facts`, `knowledge_chunks`, `hosted_apps` and `budget_usd`: every limit an operator can set, set or not; `budget_usd`'s `used` is dollars, both environments together), `lends`, `billing_url` and `world`; `used` reads what admission reads, so the page and a refusal agree, bar the simulations still playing, which weigh on `simulations` before they are counted when their call ends |
| `GET` · `PUT /v1/org/judging` | `calls` · `usage` | whether the org's calls are judged at hang-up, the model they are judged on (`model`, a `ModelConfig`; null: the platform's), and the platform's ceiling per call in dollars |
| `GET` · `PUT /v1/agents/{slug}/widget` | `talk` · `pipeline` | how the widget presents the agent per environment: `{title, tagline, greeting, accent, autostart, theme, fixed}`; a null field is the widget's own default, an accent is a CSS colour; `fixed` when the agent's class declares the look (`AgentConfig.widget`), which the GET then answers and the PUT refuses with `409 widget set by the class of …` |
| `GET /v1/agents/{slug}/pipeline` and the hold melody | `pipeline` | [pipeline-api.md](pipeline-api.md) |
| `GET` · `PUT /v1/agents/{slug}/settings`, `/v1/agents/{slug}/lexicon` | `pipeline` · `words` | [settings-api.md](settings-api.md) |
| `GET /v1/providers`, `/v1/provider-keys`, `/v1/voices`, `/v1/voices/sample` | `providers` · `pipeline` | [provider-keys.md](provider-keys.md) |
| `POST /v1/agents/{slug}/dev/{family}/{verb}` | the family's | [dev-verbs.md](dev-verbs.md) |
| `/v1/agents/{slug}/personas`, `/v1/evals/*` | `evals` | [evals.md](evals.md) |
| `/v1/org/judges`, `/v1/agents/{slug}/judges` | `evals` | the org's judges and an agent's own: [evals.md](evals.md) |
| `/v1/knowledge`, `/v1/contacts/{contact}/memory`, `/v1/agents/{slug}/memory` | `knowledge` · `memory` | [../retrieval/spec.md](../retrieval/spec.md) |
| the threads, the line, the numbers, the accounts | | [whatsapp.md](whatsapp.md) · [numbers.md](numbers.md) · [people.md](people.md) |

Money is US dollars everywhere: a call's cost, the judge's, a budget.
