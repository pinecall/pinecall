$ pinecall cases --help
Usage: pinecall cases [options] [command]

the org's dataset: real calls kept as cases — read, approve, dismiss, pull into
the repository; a golden written by hand added

Options:
  -h, --help                      display help for command

Commands:
  list [options]                  the agent's cases, the pending first; --status
                                  keeps one
  groups [options]                the agent's case groups: the calls one judge
                                  broke on, together
  show [options] <name|group>     one case whole, or one group with its cases
  propose <group>                 the judge model's diagnosis of a group: the
                                  cause and the smallest fix
  apply <group>                   the group's proposed setting, written as a new
                                  version of yours
  persona <group>                 a caller like the group's, kept as the agent's
                                  own persona
  approve [options] <name|group>  a case or a whole group approved: the nightly
                                  plays it from now on
  dismiss [options] <name|group>  a case or a whole group dismissed: the agent
                                  was right, or the judge was wrong
  reopen [options] <name>         a decided case pending again
  forget [options] <name>         a case gone; the call it came from stays
  pull [options] <name>           the case's golden as a file in the agent's
                                  goldens, to keep in the repository
  add [options] <file...>         a golden written by hand kept as an approved
                                  case, under its name
  keep [options] <call-id>        a finished call kept as an approved case, by
                                  name
  help [command]                  display help for command

A call a judge broke on is kept at hang-up as a PENDING case: its turns, the state it opened in,
and an expect that says what must not happen again. A person reads it, reproduces it
(`pinecall test --case <name>`), fixes the agent, and approves it into the nightly or dismisses it.

A case kept at hang-up joins its agent's GROUP for the judge that broke it (grp_…): propose asks
the judge model for the cause and the smallest fix; apply writes a proposed SETTING as a new
version of your settings; persona keeps a caller like the group's; approve and dismiss decide a
whole group. pull writes a case's golden into the repository; keep makes a finished call a case.

add keeps a golden written by hand as an approved case, by its name — the file's, or --name — so the
nightly plays it from the gateway and `pinecall test` with it. A case names only words: what the caller
says and what the agent must say or never say. A golden that names a state or a tool is a CODE
golden and belongs beside the code, in agents/<agent>/test/goldens/, committed with it.
