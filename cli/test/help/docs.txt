$ pinecall docs --help
Usage: pinecall docs [options] [command]

the documents the agent searches: a folder pushed into a base and pulled back, a
file removed, the bases listed, dropped, held to a golden, attached

Options:
  -h, --help               display help for command

Commands:
  push [options] [dir]     every *.md under a directory written into the base;
                           the base's other files stay
  pull [options] [dir]     the base written into the folder, file by file; a
                           file of the folder the base has not is kept
  rm [options] <path>      one file taken out of the base
  list                     every base this org pushed in the env
  drop <base>              remove a base
  eval [options] [golden]  recall@k and nDCG@10 of a golden's questions against
                           a base
  attach [options] <base>  the agent reads a base: one field of its settings,
                           written as the next version
  detach [options] <base>  the agent stops reading a base
  attached                 which agents read which base in the env
  help [command]           display help for command

The folder is a checkout of the base. push reads every *.md under the directory (agents/<name>/docs/
of the project when none is named) and writes them into the base by path; a file the base has and
the folder has not is kept, so a document added in the console survives a push. --replace makes
the base the folder, as before: what the folder has not is dropped. A README.md at the folder's
root is never sent — it describes the folder, not the business, and the agent template ships one.
pull brings the base back into the folder, one line per file: written, unchanged, or the folder's
own that the base has not (kept, never deleted). rm takes one file out of the base. The base is
the agent's slug unless --base says otherwise. list prints every base this org has pushed in the
env asked; drop removes one. These are the documents a turn SEARCHES — the RAG. What the agent
knows by heart is not a document: it is its settings' knowledge (`pinecall agent knowledge`),
read whole on every call.

attach says an agent reads a base — in your own corner, or the team's with --team, or in
production with --prod — with how a turn reads it: --k chunks, --mode (retrieved: the platform
searches before the turn; tool: the model decides when), --min-score. It is one field of the
agent's settings (`pinecall agent`), written as the next version. detach takes it out;
attached prints which agents read which base in the env asked.

eval asks the base every question of a golden — agents/<name>/test/goldens/docs.json, a JSON list of
{asks, expects}, where expects is the heading path the answer should carry — and prints
recall@k and nDCG@10, computed by code with no model in the loop, plus every question it
missed and what came back instead. A golden is fixed and the index is the variable: never
soften a question so a change can pass.

Examples
  $ pinecall docs push
  clinica-norte · 7 files · 1 kept · 41 chunks · spanish · 812 ms      # base · files sent · base's others left as they were · chunks of the files sent · stemmed in · took
  $ pinecall docs pull
  agents/clinica-norte/docs/horarios.md  written
  agents/clinica-norte/docs/precios.md   unchanged
  $ pinecall docs rm precios.md
  precios.md gone from clinica-norte

  $ pinecall docs attach clinica-norte --k 4
  clinica-norte · clinica-norte attached · your corner v4
  $ pinecall docs attached
  clinica-norte · read by clinica-norte
