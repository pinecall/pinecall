$ pinecall simulate --help
Usage: pinecall simulate [options]

a model plays one persona against the agent, live, and the call is scored at
hang-up

Options:
  --persona <name>           one of the agent's personas: pinecall personas
                             lists them; again for another caller, compared
  --judge                    read back the call.score the log seals on, and
                             print every judge
  --turns <n>                how many turns the caller improvises before hanging
                             up (default: "15")
  --voice                    a real line: a room, and the caller in a person's
                             voice
  --listen                   the call on this machine's speakers while it
                             happens; turns --voice on
  --background-noise <dB>
  --ambience <what>
  --packet-loss <share>
  --pause <seconds>          silence before each of the caller's lines, over the
                             persona's; 0 answers at once
  --via <webrtc|sip>         how the caller reaches the agent on a spoken call:
                             in its room, or ringing it by phone over SIP (the
                             sandbox's)
  --delay <ms>               the caller's network holds every packet this long,
                             0 to 2000
  --jitter <ms>              how far that hold moves from packet to packet, 0 to
                             500
  --rate <kbps>              the kilobits a second the caller's network carries;
                             a voice needs about 64
  --goal <text>              what the caller phones about this run, in the first
                             person, over the persona's goal and the briefing
  --llm <vendor/model>       the model that plays the caller this run; the
                             persona's when unsaid
  --tts <vendor>             the vendor the caller's voice is read by this run
  --caller-voice <id>        the caller's voice this run: pinecall voices list
                             names them
  --against <values>         the agent on these for this run: stt=, llm=, tts=,
                             voice=, language=, temperature=, end_of_turn=, or
                             realtime= for a model that hears and speaks; again
                             for another, compared
  --repeats <n>              how many times the caller rings under each
                             configuration, 1 to 10: more than once is a
                             comparison, read as how often each got it done
  --report [dir]             the benchmark written when the calls end, into this
                             folder (benchmark): turns --judge on
  --floor <share>            with --report: the share of counted calls a setup
                             must complete, 0 to 1 (0.9)
  --ceiling <seconds>        with --report: the middle reply a setup may take,
                             in seconds (1.5)
  --baseline <report.json>   with --report: an earlier report: each setup is
                             held against its own row there
  --gate                     with --report: exit 1 when no setup clears both
                             bars, or one fell against the baseline
  --condition <name[:line]>  with --report: the same calls placed again under
                             this line, as
                             television-20:ambience=television,background-noise=20;
                             again for each, the first being the line the others
                             are read against
  --gate-under <condition>   with --report: exit 1 unless one setup clears both
                             bars under this condition too, beside the first
                             one's line; again for another; turns --gate on
  --agent <name>
  --file <agent.tsx>
  -h, --help                 display help for command

A model in the gateway plays the caller: every turn improvised from the persona's goal, its style
and its own facts — there is no script. The agent is whoever holds it — your `pinecall start`, a
colleague's, production's with --prod; nothing is started here. The call lands in the log like
any other. --background-noise, --ambience and --packet-loss are spoken runs only, and so are --via,
--delay, --jitter and --rate: --via sip has the caller ring the agent by phone, a SIP leg in a
carrier's codec dialled into its room (the sandbox's), and --delay, --jitter and --rate are done,
with --packet-loss, to the call's real packets on their way to the room. --llm, --tts and
--caller-voice play the caller on another model or voice for this run alone; the persona keeps its
own. One of Pinecall's personas is briefed first: the gateway gives it the one concrete thing it
phones this agent about, in the agent's own terms, and keeps its manner; --goal says it yourself,
for any persona, and nobody is briefed. The caller runs on the runtime's keys unless the org brought that vendor's; each run counts
as one simulation, and what its caller cost is kept with the call. --against runs THE AGENT on
other values for this run alone — stt=, llm=, tts=, voice=, language=, temperature=, joined by
commas, as the console's test room does, or realtime=vendor/model for a model that hears and speaks
in the place of the three (a spoken call, on the org's own key for that vendor); said twice or more, every configuration is placed at
once against the same caller and the table reads them best first: the judges, then the reply time,
then the cost. In the sandbox only, with a key that edits the pipeline. --repeats rings the caller
that many times under each configuration, 1 to 10, with or without --against: one call tells whether
the agent can do it, several how often it does. --persona said again is another caller, each
against every configuration. Several runs end in a table by configuration: how many did each
caller's task, the middle reply, what they cost, and what one completed call cost. A comparison
larger than the org's simulated calls at once runs whole: the calls past it wait their turn.
--report writes the agent's benchmark when the calls end, into ./benchmark or the folder named: a
page to open or publish, report.json and each call's recording, each setup held to --floor and
--ceiling (`pinecall benchmark --help` reads them); it turns --judge on, and --gate makes it exit 1
when no setup clears both bars. With --report, --condition places the same calls again on another
line, again for each: a name, and after a colon what the line is under it, as the line's own flags
name it (ambience, background-noise, packet-loss, delay, jitter, rate, via); a name alone is the
line as it is. The first is the line the others are read against. Each condition is a comparison
of its own, placed after the one before it ended, and the report has a column for each;
--gate-under names one a setup must clear both bars under too.

Examples
  $ pinecall simulate --persona hurried --listen --turns 2
  $ pinecall simulate --persona hurried --voice --tts google --caller-voice Puck
  $ pinecall simulate --persona hurried --voice --judge --against llm=groq/openai/gpt-oss-120b       --against llm=google/gemini-3.5-flash-lite --against llm=anthropic/claude-haiku-5-5,tts=deepgram
  $ pinecall simulate --persona books-a-visit --judge --repeats 5
  $ pinecall simulate --persona books-a-visit --persona hurried --voice --repeats 5 --report --gate
  $ pinecall simulate --persona books-a-visit --persona hurried --voice --judge --repeats 5       --against llm=google/gemini-3.5-flash-lite --against llm=anthropic/claude-haiku-5-5
  $ pinecall simulate --persona books-a-visit --voice --judge --repeats 5       --against llm=google/gemini-3.5-flash-lite --against realtime=google/gemini-3.8-live
